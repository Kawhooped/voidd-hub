# VOID Living Worlds

First runnable simulation prototype for the VOID AI World Engine.

## Run

Open \`index.html\` through a static web server or deploy this folder as a static site. ES modules and browser storage may not work when opening the file directly with a \`file://\` URL.

## Current capabilities

- Four distinct marketplace residents.
- Manual actions and automatic turn progression.
- Deterministic local fallback behavior; no model API or server required.
- Separate world state, character profiles, memories, dialogue, discoveries, and event ledger.
- Browser-local persistence using localStorage.
- Action validation: the simulation only accepts configured action IDs.

## Architecture

- \`src/world.js\`: world state, character definitions, available actions, and deterministic simulation rules.
- \`src/app.js\`: browser interface, persistence, turn scheduling, rendering, and model-adapter seam.
- \`index.html\`: responsive application shell.

## Model integration boundary

The model adapter currently returns null, which selects the local fallback. To connect a local or hosted model later, implement \`modelAdapter.chooseAction(context)\` and return a structured action proposal. Validate every proposed action against \`getAvailableActions\` before calling \`takeTurn\`.

Do not put provider secrets in browser code. For a hosted provider, use a small server-side proxy. For browser-local inference, use a supported WebGPU runtime and keep model files optional.

## Known limitations

- Memories persist only in the current browser and are not synchronized across devices.
- Local fallback dialogue is authored behavior, not generated by an LLM.
- Characters do not yet act concurrently; turns are sequential.
- The model adapter is an integration seam, not a connected model.
