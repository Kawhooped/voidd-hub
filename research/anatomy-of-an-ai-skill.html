The Anatomy of an AI Skill

A conceptual model for designing reusable capabilities

DD Tech Research · Working paper · November 2026

What exactly is an AI skill?

It is tempting to define a skill as a collection of instructions. That definition is useful for describing its implementation, but insufficient for understanding its function.

Instructions are only one component of a capability. A skill must help an AI system recognize a situation, select relevant knowledge, perform appropriate actions, adapt when necessary, and determine whether the result is satisfactory.

We propose an eight-part conceptual model.

Eight components

1. Identity

What capability does the skill represent? Its identity establishes its purpose, boundaries, and intended domain.

2. Activation

When should the skill be used? Activation conditions help the system recognize relevant situations and distinguish them from unrelated tasks.

3. Knowledge

What information does the skill need? This can include domain knowledge, principles, constraints, examples, definitions, and reference material.

4. Method

How should the work be performed? The method describes procedures, decision rules, sequences, and strategies.

5. Resources

What external materials or tools are required? Resources can include scripts, datasets, templates, APIs, and supporting documents.

6. Execution

How does the capability translate into actual work? This concerns applying the method to the current task rather than merely describing what should happen.

7. Verification

How does the system determine whether the work succeeded? Verification includes checking outputs, testing requirements, identifying errors, and recognizing uncertainty.

8. Evolution

How does the capability improve? A skill should be revisable as new failures, examples, tools, and knowledge become available.

Conceptual anatomy versus file format

These eight components describe what a skill needs to accomplish conceptually. They should not be confused with a required file format.

For example, an Agent Skills implementation can use a SKILL.md file, metadata, supporting documents, scripts, and other resources. Its implementation structure is not necessarily identical to its conceptual anatomy.

The distinction matters because the same underlying capability could be implemented in different technical environments.

The central proposition

A skill is not simply stored knowledge. It is an organized capability for converting relevant knowledge into appropriate, verifiable action under particular conditions.

This definition gives us something more useful to investigate than the quality of an instruction file: the performance of the capability as a whole.

The next research question is whether these eight components can be independently evaluated and whether particular combinations consistently produce better results.
