How Do We Know an AI Skill Actually Works?

From impressive instructions to measurable performance

DD Tech Research · Working paper · November 2026

The validation problem

An AI skill can look excellent on paper and still fail in practice. It can contain detailed instructions, carefully organized references, and sophisticated procedures without producing better results than the underlying model would have produced independently.

This creates a basic research problem: How do we distinguish a genuinely useful skill from a well-written set of instructions?

Establish a baseline

The first requirement is to measure performance without the skill. Give an AI system a representative task and record its output. Then give the same system the same task with the skill activated.

The difference between these results provides an initial indication of the skill's contribution. However, a single comparison is not enough to establish reliability.

Test representative situations

  • Ordinary situations where the skill should activate.
  • Borderline situations where activation is uncertain.
  • Difficult situations requiring judgment.
  • Situations involving incomplete information.
  • Situations where the skill should not activate.

This tests more than the instructions themselves. It tests whether the system recognizes when the capability is appropriate.

Measure actual performance

  • Completion: Was the task completed?
  • Depth: Was the work sufficiently developed?
  • Specificity: Did it address the actual task?
  • Usefulness: Can the result be applied?
  • Evidence: Were claims appropriately supported?
  • Reliability: Does performance remain consistent?
  • Completeness: Were important requirements missed?
  • Efficiency: Were resources used effectively?

These dimensions should be scored separately rather than collapsed immediately into one number. A skill might improve completeness while making execution slower. Another might improve accuracy while reducing flexibility. Those tradeoffs are important findings, not necessarily failures.

Control the experiment

Comparisons should keep the model, task, available tools, and evaluation criteria consistent wherever possible. Repeated trials help reveal variability.

Evaluators should use explicit scoring rubrics and, where feasible, assess outputs without knowing which condition produced them. This reduces the risk of favoring the skill simply because it was expected to work.

The experiment should also preserve failed results. Removing failures from the record creates an inaccurate picture of performance.

A practical research protocol

  1. Select a representative task.
  2. Record the model's baseline output.
  3. Activate the proposed skill.
  4. Repeat the task under comparable conditions.
  5. Score both outputs using the same rubric.
  6. Repeat across additional tasks and trials.
  7. Document improvements, regressions, and unexpected behavior.
  8. Revise the skill and repeat the experiment.

The larger implication

This approach changes how we think about AI specialization. Instead of asking whether a skill is well written, we ask whether it produces a measurable and reproducible improvement.

A skill is not validated by its description. It is validated by what happens when it is used.
