# VOID Agent System

A portable, Git-managed operating foundation for every agent in the VOID network.

## Structure

- `CONSTITUTION.md` — shared rules, citizenship, authority boundaries and operating principles.
- `NETWORK-PROTOCOL.md` — agent discovery, messaging, task lifecycle, delegation, coordination and conflict resolution.
- `modules/website-standards-quality-authority.md` — specialized mandate and knowledge for website stewardship.
- `procedures/website-assessment.md` — repeatable inspection, scoring, remediation and verification procedure.
- `templates/AGENT.md` — individual agent identity and configuration template.

## How an agent is assembled

Every agent reads the shared Constitution, then its individual Agent Charter, then the specialized module and procedures relevant to its jurisdiction. The shared Constitution is inherited; it is not copied into every agent file.

The individual charter supplies the agent's chosen name, title, jurisdiction, three Gem Slots, booster cards, tools, permissions, current state and records.

## Operating sequence

1. Read the Constitution.
2. Read the individual Agent Charter.
3. Read assigned modules and procedures.
4. Discover the actual environment and available evidence.
5. Establish a baseline before making changes.
6. Operate within granted permissions.
7. Verify outcomes and update records.

## State and evidence

Git stores versioned instructions, procedures, configuration and durable reports. It is not a live telemetry database. Live uptime, traffic and performance measurements must come from the relevant monitoring integrations and be timestamped with their source.

## First specialized module

The Website Standards & Quality Authority module is the first reference implementation. It is designed to be assigned to an existing website and then adapted to the actual platform, content, jurisdiction and risk profile.
