# VOID Foundry Templates

Reusable starting points for VOID projects.

## Templates

- website-starter — responsive static-site foundation.
- ai-world-starter — model-independent multi-character simulation blueprint.
- interactive-app-starter — browser application with state, controls, and persistence.

## Reuse workflow

1. Choose the closest starter.
2. Copy its folder into a new project or application.
3. Change the project configuration and content.
4. Build and test the project.
5. Extract generally useful improvements back into the starter.

Keep reusable capabilities in templates or shared components. Keep project-specific content in the project itself.

## Template contract

Every starter should document:
- What it includes.
- What must be configured.
- Dependencies and runtime requirements.
- How to run and verify it.
- Known limitations.

Templates are blueprints, not claims that every listed capability is already implemented.
